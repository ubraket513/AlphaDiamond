# 학습 파이프라인 정리와 파일별 설명

사용자는 기존 파이프라인의 설정 연결 누락, 중복 구현, 불필요한 옛 진입점과 숨은 정책을 정리하도록 승인했다. 2026-10-29 추가 요청은 정리하는 파일을 직접 검토할 수 있도록 상세한 소스 주석을 작성하는 것이다. 별도 승인 절차를 반복하지 않고 실행한다.

## 방향

기존 모듈 안에서 책임과 실행 경로를 단순화한다. 새 manager, routing framework, compatibility framework, registry, 재시도나 fallback을 도입하지 않는다. 파일 수를 줄이는 것만을 목적으로 학습과 배포 SDK의 경계를 합치지도 않는다.

비교한 방식은 전면 재작성, 현 구조 위에 추상화 추가, 기존 구현의 중복 제거다. 앞의 두 방식은 진행 중인 실험과 사용자의 단순성 요구에 맞지 않는다. 사용자가 승인한 세 번째 방식으로 진행한다.

## 정리 범위

1. `ProductionConfig`의 `c_puct`가 실제 self-play 및 arena 검색에 전달되도록 연결한다. 기존 1.5 설정의 동작을 유지한다.
2. 실행에 사용되지 않는 inference queue capacity/response timeout을 새 설정에서 제거한다. 기존 체크포인트의 직렬화된 설정과 동일 설정으로 재개하는 동작은 보존한다. 기존에 허용하던 이 두 무효 필드의 값/존재 여부 변경은 재개 시 거부하도록 명시적으로 바꾼다. 지원하지 않는 기능을 작동한다고 주석에 설명하지 않는다.
3. 반복되는 Trainer 설정 변환을 기존 `train_main.cpp`의 내부 함수 하나로 정의한다. 공개 설정 헤더에 Trainer/LibTorch 의존성을 추가하지 않는다. 체크포인트 로딩은 의미가 동일하다고 입증된 중복만 합친다.
4. JSON을 확인하고 accepted만 반환하는 옛 `alphadiamond-pipeline` 실행 진입점을 제거한다. 현재 학습·평가·벤치마크가 사용하는 pipeline 함수는 보존한다.
5. 기존 보고서의 파일 접근 오류를 '보고서 없음'으로 조용히 처리하지 않는다. 아직 실행되지 않은 단계의 보고서 부재는 정상 상태로 구분한다.
6. arena의 반복 방지 정책 등 실제 적용 값을 설정/보고서/주석에서 추적할 수 있게 한다. 과거 실험의 의미를 바꾸거나 별도 정책 계층을 만들지 않는다.
7. 설정, 실행 조정, self-play, replay, model pool, learner, checkpoint 및 arena 선택 경로를 파일 단위로 설명한다. 기존 회귀 테스트와 GitHub CI는 제거하고 필요한 테스트/CI의 재설계는 사용자가 나중에 별도로 진행한다.

## 상세 주석의 기준

- 파일 머리말: 담당 책임, 주요 호출자와 피호출자, 데이터가 들어오고 나가는 경로.
- 공개 선언: 입력의 의미와 단위, 소유권과 수명, 반환 결과, 오류와 부작용.
- 복잡한 구현: 배치/스레드의 분담, 검색 루트와 모델 소유자의 관계, 상태 전이와 저장 순서, 해시/직렬화의 의미.
- 호환성 분기: 지원하는 옛 형식, 현재 정상 경로와의 차이, 유지하는 이유. 호환성과 실패 후 대체 실행을 구분한다.
- 실험 정책: 실제 적용되는 값과 설정에서 오는 값의 경계. 성능 측정과 모델 강도 증거를 구분한다.
- 단순 대입문을 그대로 읽어 주는 주석이나 동일한 설명의 복사본으로 분량을 늘리지 않는다. 사용자가 요청한 상세함은 설계 이유와 계약을 빠짐없이 설명하는 것으로 충족한다.
- 구현이 보장하지 않는 thread-safety, read-only, 자동 복구를 주장하지 않는다. 특히 ReplayStore의 열기 작업은 orphan chunk 정리를 수행할 수 있다.

## 보존할 것

현재 여섯 개 confirmation arm과 분석이 끝날 때까지 실험의 소스·바이너리·설정·모델 식별자는 고정한다. 그동안은 파일별 참조 조사와 주석/정리안만 작성한다. 실제 코드 변경은 그 이후에 수행한다. 사용자의 미커밋 자료, 체크포인트, shipped models, 기존 실험 증거는 그대로 보존한다.

수동 Stop은 존중하며, 실행기 자체 오류는 원인을 수정하고 검증한 뒤 자율적으로 이어간다. 기존 자율 실행 종료 시각 16:20:02 KST는 유지하며, 미완료 파일을 완료로 표시하지 않는다.

## 완료 증거와 최신 사용자 지시

사용자는 필요한 테스트와 GitHub CI를 나중에 처음부터 별도로 만들겠다고 명확히 지시했다. 따라서 이 정리에서는 새 회귀 테스트나 임시 테스트, 새 CI를 만들지 않는다. 기존 것을 포함한 회귀 테스트 전체와 기존 GitHub CI를 제거한다. 이전에 계획한 회귀 테스트 추가·재실행 단계는 이 지시로 취소한다.

이미 실행한 테스트·벤치마크·평가 결과는 기록으로 보존한다. 테스트 소스, 전용 fixture/golden 및 생성 도구, CTest/npm 등록, CI workflows와 실행 참조를 함께 제거한다. 실제 제품/벤치마크가 공유하는 입력은 사용처를 확인한다. SDK 합성 모델 fixture는 테스트 전용이므로 제거하지만 Desktop 런타임에 필요한 다섯 topology table은 유지한다.

남은 제품/벤치마크를 GCC/mold/sccache/Ninja로 병렬 빌드하고 실제 CLI와 패널 실행으로 확인한다. 검증용 새 wrapper나 대체 프레임워크는 만들지 않는다. 파일별 검토표에 실제 코드 정리·주석·삭제·빌드/실행 결과를 기록하며, Graphify의 제품 관계가 보존되고 삭제된 테스트 관계가 정리됐는지 확인한다.
